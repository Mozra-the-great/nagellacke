Third pre-release. One fix on top of `v3.2.0-rc.2`, relevant if you use OpenRouter.

### Why rc.3

The "nur kostenlose Modelle" switch appended `:free` to whatever model was configured. That is right for a provider-hosted model (`deepseek/deepseek-r1:free`), but `:free` is a **variant suffix on a provider model** — OpenRouter's own routers are not provider models, so the suffix built ids that aren't valid variants:

| Configured model | rc.2 sent | Valid? |
|---|---|---|
| `openrouter/auto` (app default) | `openrouter/auto:free` | no |
| `openrouter/free` (OpenRouter's Free Models Router) | `openrouter/free:free` | no |
| `deepseek/deepseek-r1` | `deepseek/deepseek-r1:free` | yes |

So the switch was broken on both realistic configurations — including the app's own default — and worked only for provider-hosted models.

Routers now map to `openrouter/free`, which is what the setting means anyway; provider models keep the `:free` variant, and an id that already carries it is left alone.

### Worth knowing

With the free-models switch **off** and a provider model configured, OpenRouter bills the request against your credit balance. The switch is the only thing standing between a funded key and paid inference — Smart-Cart in particular makes the larger calls.

Everything else is unchanged from rc.2 and rc.1 — see [rc.1's notes](https://github.com/Mozra-the-great/nagellacke/releases/tag/v3.2.0-rc.1) for the full list, **including the two deployment warnings** (per-account private collections, and 7-day sessions).

### Still untested

- **The OpenRouter path**, end to end. `openrouter.ai` is unreachable from the environment this was built in, so this fix rests on OpenRouter's model-variant and free-router documentation rather than a live call. The id mapping itself was checked across router, provider, and already-suffixed inputs.
- **Grounded web research**, which needs an API key with web-search quota. Without it Smart-Cart answers from model knowledge and is not verifying that a product genuinely exists.
- **The Android app has still not been compiled.** Unchanged since rc.1 and the main reason this is still a release candidate.
