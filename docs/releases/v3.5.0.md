# v3.5.0

Minor-Release nach gut zwei Monaten: alles, was seit v3.4.2 auf `main` gelandet ist. Schwerpunkte sind der öffentliche Instanz-Modus (nailvault.de), Datenschutz und Datensparsamkeit auf dem Server sowie Sicherheits-Fixes. Nur Web und Server; die Android-App ist eingefroren (#372, Tag `android-final`).

## Highlights

- **Aufbewahrungsfristen (#463, #464, #465, PRs #466, #467):** Ein vom Admin gelöschtes Konto wird nach **30 Tagen** endgültig entfernt (umbenannte Sammlung und hochgeladene Fotos, vermerkt in `data/pending_deletions.json`), Löschmarkierungen in Sammlungen fallen nach **90 Tagen** weg, und Fotodateien, die keine Sammlung mehr verwendet, werden nach **7 Tagen** Karenz gelöscht. Der Aufräum-Job (`src/retention.ts`) läuft beim Start und danach stündlich und loggt nur Anzahlen.
- **Berichtsempfänger mit Double-Opt-in (#449, #456, #457):** Geplante Berichte gehen nur noch an die eigene, verifizierte Adresse oder an einen Empfänger, der den Bestätigungslink geöffnet hat; bestehende Pläne an fremde Adressen pausieren beim ersten Start, ohne dass jemand angeschrieben wird. „Jetzt senden“ ist auf dieselben Adressen beschränkt, und jede Berichtsmail trägt einen Abmeldelink (RFC 8058).
- **Fotos ohne Metadaten (#451):** Uploads werden von EXIF/XMP/IPTC befreit (ohne Neukodierung, die Ausrichtung bleibt); vorhandene Fotos bereinigt eine einmalige Migration beim Start.
- **Benutzernamen ohne Groß-/Kleinschreibung (#445):** Namen werden kanonisch (NFKC + klein) gespeichert und verglichen; bestehende Konten werden beim Start umbenannt, bei einer Kollision startet der Server nicht und ändert nichts.
- **Öffentlicher Instanz-Modus (#324) und Passkeys (#228):** Schalter für Foto-Uploads und KI, Branding, Impressum/Datenschutz pro Instanz, Proof-of-Work bei der Registrierung, Einleitungsseite, Passwort vergessen, E-Mail-Bestätigung, Datenexport und Selbstlöschung, Passkeys.
- **Sicherheit:** Foto-Zugriff nur für den Uploader (#352), Foto-Tokens im Log maskiert (#450), SSRF-Schutz für ausgehende Anfragen (#401), `TRUST_PROXY` für Rate-Limits hinter einem Proxy (#397), Sicherheits-Header (#355), Abhängigkeits-Advisories (#409, #432).
- **Betrieb:** Node.js 24 (#420), Server-Image aus GitHub Actions nach GHCR (#426), das Selbst-Update blockiert den Server nicht mehr (#338) und erkennt Container-Deployments (#340).

## Für Betreiber

Beim ersten Start nach dem Update laufen nacheinander: die Umbenennung der Benutzernamen (bricht bei Kollisionen ab), die Zuordnung und Pausierung der Berichtspläne, die EXIF-Bereinigung gespeicherter Fotos (überschreibt die Originale) und der Aufräum-Job (verwaiste Fotos älter als 7 Tage, Löschmarkierungen älter als 90 Tage). **Vorher `data/` samt `data/photos/` sichern.** Self-Hoster mit `install.sh` brauchen Node 24, siehe `docs/installation.md`.
